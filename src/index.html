Como esta construido el servidor

+--------------------------------------------------------------------------------+ | SERVIDOR MULTIHILO EN C (API WinSock2 de Windows) | | | | PUERTO TCP 6000 PUERTO HTTP 9090 | | (terminal: cliente.exe / ncat) (navegador web / API REST) | | - Un hilo Win32 por usuario - GET / -> pagina web | | - Candado: CRITICAL_SECTION - GET /mensajes -> historial JSON | | - Reparto de mensajes (Broadcast) - POST /enviar -> mensaje nuevo | +--------------------------------------------------------------------------------+ | [MEMORIA COMPARTIDA PROTEGIDA POR CANDADOS] lockClients (lista de sockets) <---> lockMsgs (historial)

1. Candados para evitar condiciones de carrera

El servidor usa CRITICAL_SECTION para que solo un hilo a la vez toque los datos compartidos:

  • lockClients: cuida el arreglo de sockets conectados (máximo 10) cuando entran o salen usuarios al mismo tiempo.
  • lockMsgs: cuida el historial de los últimos 200 mensajes, que leen las peticiones GET y escriben el chat TCP, el POST y la consola del servidor.

2. Publicación en Internet

Para que otras personas fuera de la red se conecten hay dos caminos:

  • Ruta A (tradicional): reenviar los puertos TCP 6000 y 9090 en el router y usar DuckDNS para tener un nombre fijo.
  • Ruta B (CGNAT / túneles): usar ngrok tcp 6000 y ngrok http 9090, o túneles de Cloudflare.
